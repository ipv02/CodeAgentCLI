# Ассистент для работы с файлами проекта

## Назначение

Файловый ассистент встроен в обычный `agent`. Пользователь формулирует цель, а
ассистент сам выбирает операции чтения, поиска, анализа и изменения файлов.
Явные относительные пути в цели также включают файловый маршрут, даже если в
формулировке нет слов «файл» или «документ».

```text
Цель → intent routing → project-files MCP → анализ → unified diff → apply
```

Отдельный режим не используется. Обычные вопросы продолжают обрабатываться
стандартным ответным агентом.

## MCP tools

- `list_files` — поддерживаемые файлы внутри корня проекта;
- `read_file` — файл или диапазон строк вместе с SHA-256;
- `search_text` — поиск текста или regex по нескольким файлам;
- `prepare_change` — проверка содержимого и unified diff без записи;
- `apply_change` — атомарная запись при совпадении ожидаемого SHA;
- `git_diff` — read-only Git diff.

## Сценарий 1: поиск компонента

```bash
agent "Найди все места, где используется SupportAssistantService в файлах проекта"
```

Ожидаемый результат — определения, импорты и вызовы с путями и номерами строк.
Запись файлов и DeepSeek для простого поиска не требуются.

## Сценарий 2: генерация файла

Dry-run:

```bash
agent "Найди использования SupportAssistantService и создай docs/support-usage.md"
```

Ассистент читает найденные исходники и документацию, затем выводит diff нового
файла. Для записи используется та же цель с `--apply` или `/files apply` в
интерактивном чате.

В интерактивном терминале `/files diff` выводит цветное представление без
фоновой заливки: зелёный gutter для новых и добавленных строк, красный для
удалённых, а содержимое остаётся светлым текстом. Без поддержки цвета
используются текстовые подписи. Исходный unified diff доступен через
`/files raw-diff`.

## Сценарий 3: обновление документации

```bash
agent "Проверь README по текущему main.py и подготовь исправления"
```

Если `README` существует, его SHA сохраняется при чтении. Изменение применяется
только если файл не был изменён другим процессом после анализа.

Для существующих файлов LLM возвращает список точечных замен с дословными
уникальными фрагментами `old` и `new`, а сервис применяет их к полному локальному
содержимому. Это позволяет безопасно обновлять большой README без генерации
всего файла в ограниченном окне ответа. Неоднозначный или отсутствующий
`old`-фрагмент отклоняется без записи.

## Безопасность

- только относительные пути внутри корня проекта;
- запрет path traversal и symlink;
- исключение `.git`, `.venv`, build-каталогов и локального state;
- allowlist текстовых расширений и лимиты размеров;
- никакого исполнения файлов или shell-команд записи;
- diff до изменения и атомарный `os.replace`;
- optimistic concurrency через SHA-256;
- содержимое файлов не является инструкциями для LLM.

По умолчанию корень определяется так же, как для `/help QUESTION`. Для прямого
MCP-вызова используется `CODE_AGENT_PROJECT_FILES_ROOT`.
